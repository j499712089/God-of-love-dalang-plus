# 女生档案管理教程（profile_db）

> 适用对象：拿到本技能分发版的普通用户。读完后能独立完成「建库 → 建档 → 编辑 → 查排名 → 常见问题」。

---

## 1. 库根位置（规约，避免乱建文件）

默认推荐位置：

| 系统 | 库根路径 |
|---|---|
| Windows | `D:\我的档案库` |
| macOS / Linux | `~/.nvsheng/library` |

**为什么要规约**：本技能是"云端调用壳"，但每位用户的"档案库"是**本地的**（一人一个目录），不能写在技能包里（覆盖安装会冲掉）。**首次建档时必须告诉 agent 你想把库放哪**，不指定则用上表默认。

**所有自动产物必须写入用户库根，不得写回技能包**：`<库根>/data/db.js`、`<库根>/data/index.json`。如果统一配置或库根指针失效，`build_db.py` 会直接报错停止，不会回退写入技能包。

**库根下长什么样**：
```
D:\我的档案库\
├── index.html                ← 双击打开的页面
├── library.json              ← 库位置指针（自动生成）
├── library-info.json         ← 页面自动定位信息（自动生成）
├── README.md / SCHEMA.md
├── assets/                   ← 页面资源
├── data/
│   ├── db.js / index.json    ← 页面读取的数据（自动重建）
│   └── profiles/<id>.json    ← 每张档案一个文件
└── _backup/                  ← 删除前自动备份
```

## 2. 首次建档（问 AI agent 做）

直接告诉 agent：

> 「用 `恋爱之神大浪_PLUS` 这个技能帮我在 `D:\我的档案库` 建一个女生档案库，然后给这份资料建卡：[资料]」

Agent 会自动执行：
1. `python scripts/profile_cli.py init --path "D:\我的档案库"`（建库 + 写库根 pointer + 复制页面到库根）
2. `new` 建卡 → 反复 `set` / `patch` 填资料 → `validate` 验收
3. 告知绝对路径让你双击 index.html

## 3. 页面怎么用

### 3.1 打开

**Agent 首次 init 后会提供：** `<库根>/index.html`。这是静态看板，直接双击打开，不需要本机后端、端口或网络。页面读取同目录 `data/db.js`。

### 3.2 排行榜 + 详情

打开后看到：
- 顶部统计（总人数 / 推进中 / 观察中 / 已止损）
- 过滤芯片（全部 / 推进中 / 观察中 / 已止损）
- 卡片网格（按兴趣度降序）

点卡片进详情：
- 8 个分区（资料档案/兴趣度/照片解码/真实性五维/判断/关系定位/方案/时间线）

### 3.3 改档案——统一由 Agent/CLI 写入

1. 页面只展示同目录 `data/db.js`，不连接后端、不占用端口
2. 所有黄色字段修改先作为待写入内容；真实源文件必须由 Agent/CLI 写入 `<库根>/data/profiles/<id>.json`
3. 写入后必须执行 `python scripts/profile_cli.py rebuild`
4. `rebuild` 自动生成 `<库根>/data/index.json` 与 `<库根>/data/db.js`
5. 刷新 `<库根>/index.html`，以新生成的 `data/db.js` 为准

**方式 B：CLI 写入（用于把页面修改正式合并进用户库源文件）**

库根已知道的前提下：
```bash
# 改字段
python scripts/profile_cli.py --lib "D:\我的档案库" set --id linlin_tantan --field facts.年龄 --value 28

# 追加时间线
python scripts/profile_cli.py --lib "D:\我的档案库" timeline-add --id linlin_tantan --t 第3轮 --who 她 --text "在忙 晚点说" --gap 8h

# 批量合并（用 JSON 文件）
python scripts/profile_cli.py --lib "D:\我的档案库" patch --id linlin_tantan --file patch.json

# 看排名
python scripts/profile_cli.py --lib "D:\我的档案库" list

# 校验颗粒度
python scripts/profile_cli.py --lib "D:\我的档案库" validate --id linlin_tantan
```

库根忘了？运行：
```bash
python scripts/profile_cli.py --lib . where    # 当前目录含 profile_db 时
```
或直接看 `D:\我的档案库\library.json` 里的 `library_root` 字段。
> 💡 库根与许可证（key）统一存在 `~/.dalang/config.json`（Windows：`C:\Users\<用户名>\.dalang\config.json`），每次调用技能自动读取——有 key 不问 key、有库根不问库位置，缺什么才问什么。

### 3.4 页面与 CLI 的职责

| 场景 | 做法 |
|---|---|
| 查看排名和详情 | 双击 `<库根>/index.html` |
| 新建或更新资料卡 | Agent 调用 `profile_cli.py` |
| 批量导入或修改 | `profile_cli.py patch` |
| 写入后更新页面 | 自动运行 `profile_cli.py rebuild`，再刷新页面 |

## 4. 19 字段模板（写前必读）

每张档案必须含 19 个顶层字段，**缺项即返工**：

```
id, name, platform, verdict, interest, interest_breakdown,
truth_level, created, updated, facts, photos, truth_check,
truth_note, inferences, position, plan, gaps, timeline, summary
```

**兴趣度六项**（总分由脚本自动加总，禁止手填 `interest`）：
- `intent` 25 / `speed` 20 / `respond` 20 / `match` 15 / `truth` 10 / `risk` 10

**颗粒度红线**（任意一条不达即 FAIL）：
- `facts` ≥ 8 条
- `photos` 每张 `{n, content, decode}`
- `truth_check` 五维，每维 `{dim, result, level}`
- `inferences` ≥ 3 条，每条四件套 `title / confidence / evidence / readings / means`
- `position.chance` + `position.risk`
- `plan` 七项 `stage / opener / opener_why / rounds / invite_rules / stop_rules / funnel_note`
- `gaps` 至少 1 条（待确认变量）
- `timeline` ≥ 1 条（没聊过也要有"第0轮 匹配"占位）

**枚举值**（手打错会被 CLI 拒）：
- `verdict` ∈ {推进中, 观察中, 已止损}
- `truth_level` ∈ {高, 中-高, 中, 中-低, 低}

## 5. 完整 CLI 命令速查

所有命令都支持 `--lib <库根路径>` 覆盖默认；不填则按 env `DALANG_LIB` / 指针 / 默认推荐位置。

| 操作 | 命令 |
|---|---|
| 建库 | `python scripts/profile_cli.py init --path <库根>` |
| 迁移库 | `python scripts/profile_cli.py init --path <新路径> --force` |
| 看库根 | `python scripts/profile_cli.py where` |
| 查全库 | `python scripts/profile_cli.py list` |
| 查单卡 | `python scripts/profile_cli.py get --id <id> [--field <path>]` |
| 建卡 | `python scripts/profile_cli.py new --id <id> --name <名> --platform <平台>` |
| 改单字段 | `python scripts/profile_cli.py set --id <id> --field <path> --value <v>` |
| 批量合并 | `python scripts/profile_cli.py patch --id <id> --file patch.json` |
| 打分 | `python scripts/profile_cli.py score --id <id> --intent 25 --speed 20 --respond 20 --match 15 --truth 10 --risk 10` |
| 设结论 | `python scripts/profile_cli.py verdict --id <id> --value 推进中` |
| 追加时间线 | `python scripts/profile_cli.py timeline-add --id <id> --t 第3轮 --who 她 --text "..." --gap 8h` |
| 校验颗粒度 | `python scripts/profile_cli.py validate [--id <id>]` |
| 重建排名 | `python scripts/profile_cli.py rebuild` |
| 删（自动备份）| `python scripts/profile_cli.py delete --id <id> --force` |

## 6. 常见问题

**Q1：页面显示旧资料或空白**
A：确认 Agent 已将资料写入 `<库根>/data/profiles/<id>.json`，并执行 `python scripts/profile_cli.py rebuild`；然后刷新 `<库根>/index.html`。不要检查端口，也不要启动 `profile_server.py`。

**Q2：库位置忘了 / 之前装在别的目录**
A：运行 `python scripts/profile_cli.py --lib . where`（在技能包 `profile_db/` 目录下），或直接看 `D:\我的档案库\library.json` 的 `library_root` 字段。

**Q3：迁移到新硬盘 / 新电脑**
A：把整个库根目录（比如 `D:\我的档案库\`）复制到新位置 → 在新位置执行 `python scripts/profile_cli.py init --path <新路径> --force`（强制重写指针）。数据原样保留。

**Q4：技能升级会不会丢档案**
A：不会。技能包升级只覆盖 `恋爱之神大浪_PLUS/` 自身，**库根（你选的位置）完全独立**。验证：`data/profiles/` 还在库根，不在技能包。

**Q5：编辑后是否真正保存？**
A：字段退出输入框或按回车后，页面会立即回填，并保存到当前浏览器的 `localStorage`；关闭或刷新同一浏览器后仍会保留。这个保存只属于当前浏览器，不等于改写用户库 JSON。需要把修改正式写入源文件时，再让 Agent/CLI 执行 `patch` 并 `rebuild`。

**Q6：怎么删除一张档案**
A：页面「删除档案」按钮只清显示不删源文件（防误删）；CLI `delete --id <id> --force` 真删，**会自动备份**到 `_backup/<id>.<时间戳>.json`。

**Q7：多平台怎么管**
A：用平台区分 ID（如 `linlin_tantan` / `ayue_soul`），多份档案共存。`gaps` / `plan` 各自独立。详情页有「恢复原值」按钮可撤销页面编辑。

## 7. 安全与隐私

- 档案库**只在你本机**，云端只读`/v1/retrieve`检索（不存你的资料）
- `library.json` 不含任何敏感信息（仅路径指针）
- 页面直连授权是浏览器一次性，确认弹窗来源再点
- 删除档案前自动备份到 `_backup/`，误删可恢复

## 8. 一次完整工作流示例

**场景**：你在探探匹配到"琳琳"，要建档并分析

1. **截图发给 agent**：「用恋爱之神大浪_PLUS 在 `D:\我的档案库` 给琳琳建档：[截图]」
2. Agent 跑 init → new → set/patch → validate → 给你库路径
3. **双击 `D:\我的档案库\index.html`**（系统浏览器）
4. 页面看到"琳琳 67 分 推进中 探探"
5. 点连接 → 选 `D:\我的档案库` → 一次授权
6. agent 继续聊天 → 截图给你 → agent 跑 `timeline-add` + `score`
7. 刷新页面 → 排名更新
8. 你想改某字段 → 直接点改 → 松手保存

> ⚠️ 改完一定 validate（CLI）或刷新页面确认。如果不放心，先备份 `data/profiles/<id>.json` 再操作。
